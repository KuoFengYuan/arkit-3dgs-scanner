# 裝置操作：散熱、記憶體與運動

[English](DEVICE_NOTES.md) | **繁體中文**

本文件描述目前防護與取捨。熱狀態、峰值記憶體及幾何精度依裝置、場景、建置模式改變，歷史量測不是裝置保證。

## 散熱

AR、相機、LiDAR、渲染與離線處理共享裝置資源。QualityMonitor 對 serious 熱狀態提示，CaptureController 在 critical 時停止拍攝並保留資料；停止不代表已完成 ZIP 匯出。

可降低螢幕亮度、避免額外充電熱量，長掃描之間留時間降溫。先用目前格式，再實測提高解析度的代價。本專案尚未實作高解析度單張擷取，不能假設功耗或記憶體不變。分段掃描不會自動共用座標，合併需要對齊。

App 關閉環境貼圖。LiDAR 模式**有啟用**支援的 mesh 重建；相機模式沒有。點雲採固定材質減少不必要光照運算。

## 記憶體

保留 ARFrame 可能耗盡 ARKit buffer pool，但不是唯一閃退來源。Mesh、格網、解碼、RoomPlan、SceneKit、GPU 和輸出副本都會占用資源。

- 將影像、深度與信心圖複製到自有 buffer，姿態與內參用值型別；不排隊保留 ARFrame。
- 最多三個照片寫入工作；複製失敗或忙碌不消耗快門視角。
- 即時格有容量限制，必要時粗化；離線串流處理另有格網、快取與輸出預算。
- 錨點局部空間磚可降低校正後重複點，不能保證所有漂移表面永遠落在同一格。
- 優先使用原始 sceneDepth，透過時間／多視角檢核拒絕無支持的幾何。相關性很高的重複觀測不保證越掃越準。
- 共用影像 context，逐幀 autoreleasepool 限制暫存生命週期。
- 停止後先釋放 GPU 幾何並儲存有限預覽，再做重工作；詳見[大場景記憶體](LARGE_SCAN_MEMORY.zh-TW.md)。

磁碟容量取決於 JPEG 內容／品質、尺寸、深度與張數。HUD 為估計值。照片數上限不等於記憶體上限；合成測試成功也不能證明 iPhone 峰值 RSS。

## 曝光模糊與捲簾快門

影像曝光需要時間，各行也可能在不同時間讀出。快速旋轉即使短曝光仍可能產生幾何扭曲；單一記錄姿態不能完整描述影格內的變形。

品質監測以焦距、旋轉、平移、距離、曝光與讀出假設推估像素風險。目前設定為 10 px 提醒估計、24 px **曝光模糊**遮斷，另有嚴重速度與實測清晰度閘門，詳見[擷取一致性](LIDAR_QUALITY_AND_PREVIEW.zh-TW.md)。推估風險不是實測模糊。

補光以縮短曝光、減慢移動與轉向，保留側向基線並避免急轉。過嚴的風險門檻可能只阻擋正常走動，不能證明幾何更好。融合後只有實測細節偏弱才要求檢查／補拍；單純運動估計與資料不足保留在可展開資訊。

## 相機控制與其他細節

HUD 提供曝光／白平衡鎖定，支援的裝置另有曝光補償、快門、ISO、白平衡及對焦控制。自動對焦仍可使用；匯出保存逐幀內參，不依賴單一鎖焦校準。手動快門／ISO 須取捨亮度、雜訊與模糊；曝光鎖定在窗邊與暗角切換時可能過曝或欠曝。

逐像素處理、匹配、融合、幾何打包與 UI 協調分開。主執行緒仍有必要複製與場景套用，改熱路徑須在目標建置模式量測。Debug 與 Release 可能差很多。

相機模式保留已驗證且取色的稀疏點，可選固定姿態影像重建；不是未過濾的灰色 rawFeaturePoints。白牆與基線不足仍可能沒有可靠幾何。
