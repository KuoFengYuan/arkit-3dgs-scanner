# 實驗性局部表面重建

[English](SURFACE_RECONSTRUCTION.md) | **繁體中文**

LiDAR 掃描設定新增預設開啟的「表面重建（實驗）」。它包含相機姿態精修。「精細掃描」控制項會顯示此依賴關係，表面重建開啟時無法單獨關閉精修。關閉表面重建即可與原本 voxel 融合比較；原本以影像特徵進行的精細掃描仍可獨立選擇。純相機掃描不變。歷史紀錄的「優化訓練資料」會啟用新方法並建立另一份結果，保留原始照片與深度。

## 處理流程

1. 先執行既有影像特徵精修與通過驗證的閉環修正。
2. 新增有資源上限的局部 RGB-D 對齊：每八幀區間保留兩個固定錨點，只修正中間影格，同時最多持有三張深度／影像。最多五輪點到平面求解採用穩健殘差權重；單面牆等約束不足的系統直接拒絕。修正不得超過 3 公分或 1.5 度。同一批保留驗證像素與參考影格至少 95% 必須仍能觀測；消失的對應會計入至少 3 公分深度誤差與影像誤差懲罰，不直接忽略。完整驗證分數的深度 RMS 須至少改善 5%，且通過影像亮度誤差不惡化的檢查。這是局部剛體精修，不是完整的 COLMAP 聯合 BA，也不保證全域精度。
3. 修正後姿態同時驅動原本 voxel 融合與稀疏 TSDF 表面模型。TSDF 使用 8³ 區塊、三個 voxel 的有向距離截斷帶與預設 32 MiB 區塊估算預算；每張已儲存影格對每格最多投一票。只整合近距融合範圍內、通過深度一致性過濾的量測點；ARKit 推論 mesh 不會成為 TSDF 觀測，遠距補洞經 voxel 備援進入輸出（見[距離優先](LIDAR_SURFACE_CONSENSUS.zh-TW.md)）。
4. 只在至少兩張影格支持的正負距離交界擷取表面點，不用未知區域生成表面。輸出取樣受匯出點數上限限制。這版輸出的是彩色表面點雲，**尚非貼圖網格或高斯潑濺**。

## 備援與資源限制

原本融合與實驗性表面模型並行保留，以便提供完整備援。32 MiB 預算包含格子陣列與估算的區塊開銷，不代表整個程序的記憶體；來源點、舊融合格、ARKit 與匯出陣列另有成本。可用空間低於 512 MiB 時會釋放 TSDF；原有系統壓力監測與 192 MiB 保留空間仍會在必要時安全中止整個融合。

較久未用的區塊會分頁至獨立暫存目錄，背景資料估算預算為 256 MiB。LRU 分頁保留完整 Float 格子狀態，不降解析度或量化。正常釋放模型時移除暫存檔；表面支持遮罩只可加入已知區塊，兩種索引均依區塊預算限制大小。瞬間 I/O 緩衝與被移出的參考另有開銷，不含於常駐格子估計。磁碟失敗或用完背景預算時捨棄實驗性結果，使用完整原融合。

距離交界會標記附近受到支持的格子。缺洞、沒有兩視角 TSDF 支持等區域，仍保留該鄰域之外的原融合點，不改座標與顏色。混合結果遵守原本輸出點數上限，且須達原匯出的 35%，否則回到原結果。`completedWithFallback` 明確標示混合成果。涵蓋率與密度檢查不能證明真實幾何精度。

`pose-refinement.json` 的 `localSurface` 記錄接受／拒絕數量、已接受影格的保留驗證 RMS 平均值、前後改善、最多持有影格數、最大平移與耗時。`refusion-progress.json` v6 的 `surface` 記錄狀態、區塊配置估計、涵蓋率、交界數、備援點數、磁碟讀寫與耗時；仍可讀取舊版報告。診斷會區分成功重建與容量、記憶體、涵蓋或密度備援。

## 驗證與比較

執行 `bash tools/test_surface_reconstruction.sh` 可驗證合成場景的姿態、退化幾何、深度雜訊、區塊交界、輸出上限與資源中斷；另需執行既有融合記憶體、訓練品質、尺度／閉環與語系測試，並依序建置 iPhone／模擬器。

實機比較時，在相同且靜止、光線均勻的空間分別開關表面重建，或比較保留的歷史原始紀錄與優化副本。獨立量測已知距離，檢查牆面厚度、邊緣重影、缺面、報告狀態與耗時。合成場景修正成功與建置通過，不代表真實場景已達公分精度。反光／透明表面、動態物件、幾何約束不足與 ARKit 漂移仍有限制。本次沒有新增手機端高斯訓練。

## 保持取樣精度的融合加速

TSDF 也會重用連續區塊查詢，不改觀測順序或算術；測試會比較分頁／快取結果與記憶體／參考路徑逐 bit 相同。另兩項加速與實驗性表面方法獨立：每個雙線性格子只用一個 bit 快取原有深度／信心／邊緣判定；只預先解碼下一張 JPEG，讓影像工作與依序進行的幾何融合重疊。解碼器、尺寸、插值方式相同；影格插入順序、深度取樣、一致性門檻、點數上限與 Float 幾何／色彩計算均不變。有效性遮罩計入既有 2 MiB 深度快取。預讀啟動須至少有 512 MiB 空間，且排程前檢查單幀工作空間，不會一次排入全部照片。

v6 報告記錄 `preparedDepthSampling`、`rgbPrefetch`、`rgbWaitSeconds` 與 `wallSeconds`。JPEG 工作時間與融合重疊，不可相加當成總耗時。執行 `bash tools/test_surface_reconstruction.sh --benchmark /path/to/scan` 會交錯重跑參考／加速流程，檢查排序後座標、RGB、信心分數逐 bit 相同，並從耗時摘要排除首次暖機。`--replay /path/to/scan` 可取得局部姿態與混合表面診斷。桌面重跑以固定記憶體額度啟用手機的有界路徑，不代表 iPhone 記憶體或耗時量測。兩者唯讀來源資料，只將診斷寫入暫存目錄。新增姿態精修／TSDF 是額外品質工作，因此完整新流程不一定比原本僅 voxel 的流程快；速度比較應使用相同重建方法。

### 本機重跑證據（2026-09-22）

使用一組 399 張本機掃描資料，在關閉表面模式的相同條件下交錯測量桌面融合。參考路徑耗時中位數 5.57 秒，精確預讀／有效性快取為 3.10 秒，牆鐘耗時約縮短 44%。排除首次暖機後，有兩次參考與三次加速量測；全部六次的排序後 XYZ、RGB 與信心分數均逐 bit 相同。這是檔案系統暖機後的 macOS 基準，不代表 iPhone FPS 或完整重建時間；可用上述指令在其他資料集重現比較。

同組資料的獨立局部對齊接受 348 個中間相機候選中的 28 個。只計算已接受影格，其平均保留驗證 RMS 由 11.52 mm 降至 10.42 mm；其他姿態保持原樣。表面重跑完成並輸出 111,942 點，其中包含未支持區域保留的 11,822 個原始融合點，已觀測區塊交界涵蓋率 84.6%。常駐區塊配置約 32 MiB，暫存區塊約 51 MiB。這些是演算法診斷，不是 App 實測峰值記憶體或真值牆厚；點數較少本身不代表精度更好。此次重跑隔離新局部步驟，未重新執行整套既有特徵 BA／閉環流程。
