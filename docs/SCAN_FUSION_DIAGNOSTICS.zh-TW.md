# 融合速度與表面重影

[English](SCAN_FUSION_DIAGNOSTICS.md) | **繁體中文**

## 執行最佳化版本

共用的 `arkit-3dgs-scanner` scheme 現在將 **Run 設為 Release**，與既有的 Profile／Archive 一致。需要以 `-Onone` 逐行除錯時，選擇 `arkit-3dgs-scanner-Debug`；測試與 Analyze 仍使用 Debug。Release 維持相同的 App 識別碼與掃描儲存位置，切換 scheme 不必移除 App。個人簽章設定由本機開發者管理。

`capture-meta.json` 與第 9 版 `refusion-progress.json` 新增可選的 `debugAssertionsEnabled` 欄位；舊檔案缺少欄位仍可讀取。標準未最佳化 Swift 建置為 true、標準最佳化建置為 false，命令列重播也適用。它記錄 assertion 模式，不是完整 Xcode 組態名稱；自訂編譯器 assertion 選項可能改變此值，也不代表裝置耗時或溫度。

不要把未最佳化 Debug 的耗時當作正式效能。比較時應維持同一裝置、建置組態、掃描、姿態、重建選項與溫度狀態。診斷分別記錄 TSDF 儲存讀寫、表面處理、深度一致性與總時間。

## 保守的表面複核

相近的深度影格可能共同支持一層殘影，缺少足夠獨立視角來排除它。實驗性 TSDF 成功擷取表面後，新增跨整段路線的複核，使用與融合完全相同的最終姿態，逐張檢查最多 64 張儲存深度圖，**同時只持有一張**。

- 所選相機中心彼此至少相距 8 公分，依序選取的時間至少相隔 0.25 秒。原地連拍不會累積額外獨立票數；超過參考上限時，會沿整段路線取樣。
- 只有 3 公尺內、高信心、通過既有邊緣檢查且局部深度跨度不超過 3 公分的雙線性取樣區域能投票。沒有信心圖、幾何被排除、姿態無效或尺寸不支援的影格不能投票。
- 只有至少三個獨立參考視角判定點位明顯落在已量測的空氣中，差距超過既有深度容許值的**兩倍**，且支持它的參考少於兩個時，才會移除。兩個支持視角即可保護真實薄面，不會因其他視角不同意就刪除。
- 遮擋、缺測、遠距與畫面外觀測都不算反對票；證據不足的點保留。不移動點、不擬合或壓平牆面，保留點的 XYZ／RGB 不變。
- 若預計移除超過 10% 的點，保留完整輸入並記錄 `excessiveConflictFallback`。參考不足或中斷也保留輸入；是否發布結果仍由既有取消／記憶體守門條件決定。

兩組 `UInt8` 計數器每點使用 2 bytes，25 萬點約 0.48 MiB。完成所有投票並通過條件後才原地壓縮陣列，不建立第二份輸出點雲。複核前會釋放既有 TSDF。`surfaceValidation` 記錄參考張數、受保護點數、預計／實際移除點數、計數器空間、狀態與耗時。可設定 `CaptureConfig.surfaceVisibilityValidation = false` 進行受控重播比較，單純體素融合的回退路徑維持原樣。

這項複核針對**缺乏支持的前景殘影表面**，無法判斷玻璃的真實側面、解決被不透明牆面遮住的多層殘影，或修復所有影格共同的姿態／深度偏差。有限參考取樣也可能漏掉有效支持。原始照片與深度保留；若要依賴尺寸，仍需檢查重要薄物與透明結構。局部點雲厚度包含真實結構，不等於以真值驗證的尺寸誤差。

## 可重現驗證

執行 `bash tools/test_surface_reconstruction.sh` 與 `bash tools/test_fusion_memory.sh`，再依序完成未簽章 iPhone 與 Simulator 建置。表面測試涵蓋殘影排除、相近平行薄面的保護、遮擋、不可靠深度、缺少信心圖、重複相機位置、取消與大量衝突回退。重播需同時比較幾何、覆蓋率與時間；點數減少不代表精度提升。

TSDF 插入也會跨相鄰點重用最後一個常駐區塊，半體素步進重複命中同一格時避免再次讀取。運算順序、每影格一票、LRU 時戳、解析度與配置預算均保留。測試可用 `SurfaceTSDF(cacheBlockLookups: false)` 隔離比較。

## 本機重播證據（2026-09-23）

M1 Pro 唯讀重播使用儲存的最終姿態與深度圖、相同的 2 公分 TSDF，注入固定 6 GiB 可用空間以走手機的受限記憶體路徑。沒有將掃描或照片提交到專案。

| 掃描 | 點數：前 → 後 | 局部厚度中位數：前 → 後 | 缺失的受測區域 | 10 公分佔用格保留率 |
| --- | ---: | ---: | ---: | ---: |
| 377 張（這次回報牆面重影） | 74,810 → 72,464 | 3.676 → 3.527 公分 | 0 / 2,626 | 98.59% |
| 399 張 | 105,576 → 104,202 | 5.328 → 4.991 公分 | 0 / 2,523 | 99.17% |
| 569 張 | 250,000 → 247,021 | 1.678 → 1.529 公分 | 0 / 2,878 | 99.37% |

厚度是固定半徑 20 公分 PCA 區域中，沿法向的 P10–P90 深度帶寬。區域包含家具與真實層次，這些數值**不是牆面尺寸誤差**。受測區域沒有缺失，也不能證明每個薄物都完整保留。保留點的 XYZ／RGB 都是原結果的精確子集合；377 張掃描由兩個獨立程序產生的最終輸出位元組相同。姿態檔與原始照片／深度皆未修改。

這組 377 張掃描在同一台 Mac，以舊程式執行 **`-Onone` 需 134.92 秒，`-O` 約 5.03 秒**，排序後的 XYZ／RGB 完全一致。使用者提供的手機報告為 99.44 秒，但未記錄建置模式，因此 Debug 是有證據支持、仍待確認的診斷，不能宣稱已證實手機裝的是 Debug。包含新增複核的兩次最終最佳化重播為 5.09／4.87 秒；舊版最佳化兩次為 5.03／5.03 秒。TSDF 計算約從 2.71 降至 2.41 秒，新複核增加約 0.15 秒。增加驗證後，整體最佳化耗時大致持平；預期最大的實際速度改善來自執行最佳化 App。桌機結果不能推算手機秒數、溫控或保證不閃退。
